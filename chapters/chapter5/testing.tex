\chapter{Testing and Quality Assurance}

Software testing is an indispensable phase of the development life cycle for the JUST Undergraduate Final Admission System (JUST-UFAS). It ensures the reliability, security, and correctness of the system before it is deployed for the 2026 admission session. This chapter details the multi-layered testing strategy employed, ranging from automated unit tests to manual functional verification.

\section{Automated White Box Testing with Vitest}
As the system is built on the Next.js framework, we utilized \textbf{Vitest} for high-performance unit testing. White box testing allows us to verify the internal logic, functions, and components of the application.

\subsection{Component Rendering Tests}
Using \textit{Vitest} alongside \textit{React Testing Library}, we ensured that the core UI components render without crashing.
\begin{itemize}
    \item \textbf{Verification Point:} We tested the rendering of the landing page, navigation bar, and admission form.
    \item \textbf{Outcome:} The tests confirmed that the "JUST-UFAS" title and essential action buttons are correctly mounted in the DOM.
\end{itemize}

\subsection{Logical and Utility Function Testing}
We implemented unit tests for independent functions that handle sensitive data logic.
\begin{itemize}
    \item \textbf{Date Formatting:} A utility function was tested to ensure that ISO strings from the database are converted into user-friendly formats (e.g., "DD-MM-YYYY") for admission deadlines.
    \item \textbf{GPA Calculation:} Functions responsible for validating GST scores against department-specific eligibility criteria were tested with various edge cases.
\end{itemize}

\section{Backend API Testing with Postman}
To ensure the robustness of our RESTful APIs developed with Node.js and Prisma, we conducted extensive testing using \textbf{Postman}.

\begin{itemize}
    \item \textbf{Endpoint Integrity:} We sent various HTTP requests (GET, POST, PATCH) to endpoints like \texttt{/api/applicants} and \texttt{/api/auth}.
    \item \textbf{JSON Schema Validation:} Verified that the backend returns the correct JSON structure. For instance, the applicant list API must return an array of objects containing valid GST IDs and merit positions.
    \item \textbf{Status Code Verification:} Ensured that the server returns appropriate status codes: \texttt{200 OK} for success, \texttt{401 Unauthorized} for invalid logins, and \texttt{400 Bad Request} for malformed data.
\end{itemize}

\section{Manual Functional Testing}
Manual testing was performed to simulate real-world user behavior and ensure the system's usability from a student and administrator's perspective.

\subsection{Form Validation Testing}
The admission form is the most critical part of the student module. We performed exhaustive manual tests on all input fields.
\begin{itemize}
    \item \textbf{Empty Field Validation:} Attempting to submit the form without mandatory fields (e.g., Permanent Address) triggers an immediate error message via Tailwind-styled toast notifications.
    \item \textbf{Input Constraints:} We tested numeric fields to ensure that character inputs are restricted, preventing potential database errors.
\end{itemize}

\subsection{Role-Based Access Control (RBAC) Test}
We manually verified that the security boundaries between different user roles are strictly enforced.
\begin{itemize}
    \item \textbf{Verification:} A student account was used to attempt access to the Dean's approval dashboard (\texttt{/admin/dean}).
    \item \textbf{Result:} The system successfully redirected the user to the login page, proving that the middleware protection is functioning correctly.
\end{itemize}
